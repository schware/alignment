# ADR-0005: 경력 타임라인을 정확히 고친다 (ADR-0002의 스킬 baseline을 Supersede)

- **Status**: Accepted — ADR-0002를 Supersede함(스킬/타임라인 부분만;
  ADR-0002의 전환 목표 시점, 시장, 기존 포트폴리오 없음이라는 사실은
  그대로 유효)
- **Date**: 2026-09-06
- **Deciders**: 본인

## Context

ADR-0002는 스킬 baseline을 평평한 목록(C, C++, C#, Java — 서버통신 +
POS Client)으로 기록했는데, 이건 서로 다른 네 개의 언어/트랙을 구분 없는
덩어리로 뭉뚱그린 것이었다. 같은 날(2026-09-06) 두 차례의 후속 대화에서
— 이 ADR의 첫 버전이 다른 어디에서도 아직 참조되기 전에 — 실제 구조가
드러났고, 이게 중요했다: 이건 서로 무관한 네 개의 경험이 아니라, 하나의
일관된 도메인 안에서 약 16년에 걸친 작업이었고, 최근 8년에 뚜렷한 무게
중심이 있다. 두 정정이 같은 자리에서, 이 ADR의 첫 버전에 아직 아무것도
의존하기 전에 나왔기 때문에, 정정마다 별도의 Supersede ADR을 새로 만드는
대신 이 한 리비전으로 합쳤다 — 언제 in-place 수정이 괜찮고 언제 새
Supersede ADR이 필요한지는 이 저장소의 ADR-0001 논의 참고.

## Decision

정정된 타임라인을 앞으로의 baseline으로 기록한다:

- **총 경력: 약 16년**, 전부 리테일/커머스 기술 도메인 안에서(데스크톱
  Client/Server 소프트웨어, POS Client 소프트웨어, 서버 통신 프로토콜,
  ADR-0004의 백화점/쇼핑몰 사례 같은 멀티스토어 시스템을 위한 백엔드
  REST/Batch 서비스).
- **1~4년차**: MFC 기반 Client 및 Server 개발(Windows 데스크톱). 명시적으로
  하나의 지속된 프로그램에 대한 작업이 *아니었음* — 더 다양하고 짧게
  끝나는 프로젝트성 작업에 가까움. 이후 트랙들처럼 깊이의 축이라기보다는
  기초 경험에 가깝다.
- **5~8년차**: C++ 서버 사이드 개발, 독립된/전담 트랙으로(ADR-0004에서
  다룬 IOCP 기반 멀티테넌트 시스템이 이 시기).
- **5~16년차(12년, 5년차부터 경력 끝까지)**: C# POS Client 개발 — C++
  트랙(5~8년차)과도, 이후 Java 트랙(9~16년차)과도 동시에 진행되며 계속
  이어짐. 경력 전체에서 가장 오래 지속된 단일 실이다.
- **9~16년차(최근 8년)**: Java + Spring Boot — REST API 개발과 Batch
  처리. 가장 최근이면서, 지속된 깊이로 보면 현재의 주된 전문 분야다.

이건 이번 전환의 서사를 다시 잡는다: "포트폴리오를 처음부터 시작하는
엔지니어"가 아니라, **16년 시니어 엔지니어가 꾸준히 쌓아온 깊은 엔터프라이즈
경험을 새로운 언어와 패러다임으로 일반화하는 프로젝트** — ADR-0004의
논지(같은 architecture 판단력이 언어를 넘어 이전된다)와 ADR-0003의
전략(Backend/Platform, AI/ML, DevOps/SRE 전부에 걸치는 Platform 하나)을
직접 뒷받침한다.

## Alternatives considered

일반적인 의미로는 해당 없음 — ADR-0002와 마찬가지로 이건 선택지 중
고르는 게 아니라 정정된 사실 패턴을 기록하는 것이다. 이 저장소 자체의
ADR-0001 규칙에 따라 ADR-0002를 고치는 대신 이를 Supersede하는 새 ADR로
작성했다.

## Consequences

- 이후의 모든 ADR/README/포트폴리오 서술은 이걸 "0부터 시작하는 커리어
  전환"이 아니라 "시니어 엔지니어의 언어 간 일반화 프로젝트"로 프레이밍해야
  한다 — 이건 이 저장소 전체를 리뷰어가 어떻게 읽어야 하는지에 실질적으로
  영향을 준다.
- 이 ADR 직전 대화에서 짚었던 Batch 공백이 처음 보였던 것보다 더
  중요해졌다: Batch 작업은 최근 8년 *전체*에 걸쳐 있다, 곁다리 스킬이
  아니라 — 새 스택에서 증명할 수 있는 가장 깊고 입증 가능한 구체적
  기술 자산일 가능성이 높다. 아직 안 정해진 것(이 ADR 시점까지): 어떤
  언어로 만들지, `ROADMAP.md`의 어느 Phase에 넣을지.
- ADR-0002의 뭉뚱그린 "기존 포트폴리오 없음"도 전체 타임라인이 드러난
  지금 다시 확인해볼 만하다 — 16년이면 아직 언급 안 된 다른 전문적
  결과물(자격증, 사내 도구, 컨퍼런스 발표 등)이 있을 수 있다. 여기서는
  어느 쪽으로도 가정하지 않고, 열린 채로 표시만 해둔다.
